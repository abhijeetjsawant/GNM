# The substitution ladder — MAMMA's pipeline beside ours, one part at a time

**Current state lives in `docs/LADDER_STATUS.md`** (generated from `docs/ladder-status.json`
by `tools/compare/status.py`; never hand-edit it). This document is hand-edited and holds the plan.

**Snapshot: 2026-09-02.** Plan of record for *how the body lane is measured against
MAMMA*. The living page is `docs/substitution-ladder.html`, generated by
`tools/compare/ladder.py` and published at
<https://claude.ai/code/artifact/56361ab8-b5a0-456d-9171-4d6a09d6c132> — republish to that URL, never to a new one;
the history is `docs/ladder-history.jsonl`. Read §1 before

is also a research-licensed instrument that never ships (CLAUDE.md). Both facts shape
the method below.

## 1. Standing rules — instructions, not history

**Replace one part at a time.** MAMMA is a stack of separable stages and every one of
them leaves an artifact on disk. A rung of the ladder changes *exactly one* stage of
the pipeline and lets MAMMA's retained output supply every other stage, so that when a
number moves, one thing moved it. A figure measured while two parts changed attributes
to neither. End-to-end is the *last* rung, deliberately: it cannot attribute, and the
rungs above it exist so that it does not have to.

**Every configuration with a MAMMA part in it is an instrument.** It never ships, and
no shipped constant, threshold, weight or calibration may be fitted on it. This is not
a footnote; it holds per rung. The delivery path is the *ours* column all the way down.

**One instrument per rung, and the rung names what it is blind to.** Reprojection
cannot score depth; a length invariant cannot score direction; a tracking gate cannot
see a constant offset. The blindness is written on the page beside the figure.

**No gate a constant can pass; no gate no oracle can pass.** Every figure ships beside
a control arm that must fail (a constant, a shuffled pairing, a fixed axis) or an
oracle arm that must pass (the reference's own answer through our frames). The page
flags any rung whose figures have neither.

**Same denominator, and numbers from different references never share an axis.** Each
figure carries its reference beside it. The pose rung and the delivered rung share a
reference (MAMMA's `pred_joints` on 15 joints) and may sit on one axis; nothing else
may. There is no column called "mm vs MAMMA".

**Regenerable or absent.** Every rung on the page carries its regenerate command with
the interpreter that works: the two swap-harness instruments need the *system* `python3`
(`verts_512.pkl` unpickles torch tensors), everything under `tools/compare/` needs
`.venv/bin/python`. A figure enters the ladder only from a JSON report under
`artifacts/` written by a script in the repo. A number that lives in a document is
listed as *instrument missing* until its script writes a report. Two instruments
(`swap_true.py`, `association_swap.py`) were converted on 2026-09-02 for exactly this
reason; two more (`mamma_residuals.py`, `hand_fit.py`'s held-out protocol) still need it.

**Every subject pairing goes through `tools/head/subject_map.py`.** MAMMA's
`body_id-00` is our subject 1 on this fixture, and pairing by index corrupts only the
comparisons.

**The ladder is updated in the same pass as the measurement.** Run
`.venv/bin/python tools/compare/ladder.py` after any instrument writes a report. It
appends a history line only when a headline figure changed, and the page shows each
figure's delta against the previous entry — *better* or *worse*, per figure, with the
direction that counts declared in the registry. That is how a change that helps one
rung and hurts another is caught instead of averaged away.

## 2. MAMMA, divided as its own code divides it

From `.cache/mamma` and the retained run `artifacts/mamma/mamma-4cam-five-second-v2`
(four cameras, frames [60, 210), two performers, `pushing_and_lifting_from_ground`):

| # | stage | MAMMA's implementation | artifact on disk (the interface) |
|---|---|---|---|
| 0 | capture + calibration | `ma_cap`: intrinsics/extrinsics from the rig's calibration files, undistortion, frame window | `ma_cap/<take>/gt/<cam>.npz` (`cam_int`, `cam_ext`, image size), `global.npz` |
| 1 | person masks + per-view id | `ma_masks`: YOLO + SAM2 tracklets, CLIP feature bank, epipolar anchor across views | `ma_masks/.../<cam>/masks.npy`, `subject_feature_bank.npy` |
| 2 | 2D landmarks | `ma_2d`: MammaNet, 512 dense surface landmarks + log-sigma + visibility + contact channels, per subject, native 3840×2160 | `ma_2d/<take>/<cam>.npz` — `landmarks (150,2,512,3)`, `visibilities`, `contacts`, `floor_contacts` |
| 3 | cross-view association / re-ID | inside `ma_3d`: `mvpose_style_associate_and_triangulate_temporal`, once, before the fit | re-assigned `pts2d` (in memory), `reid_debug/` |
| 4 | triangulation | inside `ma_3d`: `triangulate_batch`, DLT, visibility-weighted, all 512 points | `smplx_params_*.npz: triangulated_3d_pts (150,512,3)` |
| 5 | temporal | no separate stage: all frames optimised jointly; runs 3–4 carry `angular_acc_loss` and `pts3d_temp_loss` (verified in the retained `run_config.yaml`; runs 1–2 have every temporal term commented out) | — |
| 6 | body shape | inside `ma_3d`, run 2: 16 betas free with `body_shape_prior_loss` | `smplx_betas (1,16)` |
| 7 | pose | four Adam runs on Geman-McClure reprojection of the 512 landmarks + L2 to the triangulated points (run 1) | `smplx_pose (150,165)`, `smplx_translation` |
| 8 | hands | the 45+45 hand values of the same fit | inside `smplx_pose` |
| 9 | head | a *locked-head* SMPL-X: jaw and eyes zero | inside `smplx_pose` |
| 10 | feet + contact | contact channels from `ma_2d`, `smplx_contact` / `smplx_floor_contact`, run-4 intersection loss | `smplx_contact`, `smplx_floor_contact` |
| 11 | mesh + skeleton | `get_smplx_forward` | `verts_joints_*.npz: pred_vertices (150,10475,3)`, `pred_joints (150,127,3)` — **`gt_*` are byte-copies of `pred_*`; never score against them** |
| 12 | overlay evidence | `ma_vis` | `ma_vis/overlay/<cam>.mp4`, `scene.rrd` |

Two things this table settles that the parity board had left open. MAMMA's temporal
smoothing is *inside the fit*, in runs 3 and 4, not a separate filter — so "MAMMA's
mesh is 2.6–2.9× smoothed" is a property of its objective, and any comparison of our
smoother against its mesh is comparing a filter to a loss term. And MAMMA's fitter
accepts only its own 512-landmark definition: `use_sparse_body_ldmks` selects a subset
of *those* (`self.body_idx`), not arbitrary joints, so "our detector into MAMMA's
everything-else" needs a mapping onto SMPL-X joint targets before it can be built.

What the ladder says today, read top to bottom: **the front end reaches the
reference and the rig throws it away.** Given MAMMA's 2D our geometry lands at its
floor (rung 4); given our 2D our triangulation sits at 36–41 mm on the joints (rung 7)
and a parametric body driven by that capture at 28–40 (rung 7, instrument); the
delivered rig sits at 113–152 (rung 11). The ~100 mm is rung 6's absence in the
delivery path — a body model — not the detector and not the fit. Hands, feet and head
each have their own axis and their own gap and none of them is inside those figures.

## 4. The replacement order — which part next, holding the rest

> **Superseded 2026-09-02 by `docs/LADDER_EXECUTION_PLAN.md`**, made with Codex (xhigh) and
> Sol reviewing the same brief independently. Two premises below were wrong: the shape
> fit is not one part and is not next, and the delivered foot has been solved from
> `ToeBase` since f6a4973, so the feet instrument now scores the solver against its own
> input. Kept as the record of what was proposed before review.

The user's instruction, recorded as the build sequence: **tackle one part at a time,
using MAMMA's other parts as instruments meanwhile, and only assemble when every part
has its own measurement.** The order below is by *what the ladder can attribute today*,
not by what is easiest.

1. **Shape into the delivery path (rung 6).** The largest measured loss, and the only
   rung where the instrument (SMPL-X, research) and the shipping candidate (MHR +
   momentum, Apache/MIT) are both on disk. Gate: rung 7's *sized* arm must move toward
   rung 7's SMPL-X arm on the same 15 joints — the two share a reference, so that is a
   legal comparison. The MHR prototype must write a report before it counts.
2. **The pose rung's other direction (rung 7).** MAMMA's `pred_joints`, mapped through
   the scoreboard's `PAIRS` onto our 19-joint contract, into `positions_to_body_track` —
   buildable from disk today, isolates our retarget on MAMMA's *fitted* joints, and
   prices the converter defect the plan already records (36–47 mm on the arms,
   clavicle origin). Not `triangulated_3d_pts`: those are 512 surface points and the
   converter takes joints. No new code in MAMMA needed.
3. **Give the 2D rung a discriminating instrument (rung 2).** `mamma_residuals.py` and
   `sam3d_ladder.py` exist and print; JSON output and registration turns the bulk
   ratio and the coherent bias into tracked figures with history. The detector is the
   half of the end-to-end gap the rig does not explain, and it is currently the rung
   with figures and no control arm.
4. **Score MAMMA's feet (rung 10).** The bar has never been measured on this footage;
   until it is, nothing about feet can be claimed in either direction. Retained
   `pred_joints` has the ankle and toe joints; `subject_map.py` pairs them.
5. **Hands: the held-out protocol as a report (rung 8).** The instrument is right and
   the number is in a document. Register it, and the thrashing defect gets a tracked
   figure instead of a paragraph.
6. **Our detector into MAMMA's fitter (rung 2, other direction).** The rung the
   substitution idea most directly asks for, and the one that needs new work: a mapping
   from our 17 joints onto SMPL-X joint targets and a Modal run of `run_ma_3d.py`.
   Instrument-only by construction; decide it after 3 shows whether the detector gap
   is bulk or bias.
7. **Calibration (rung 0), by building the owned fixture** — BODY_LANE_PLAN.md §0's
   rank 0, unchanged. It retires "not owned" on the top rung and, with it, the
   instrument-only status of every configuration below it.

Rungs 1 (masks) and 5 (temporal) stay as they are on purpose: nothing of ours consumes
masks, and the temporal rung has no valid reference until single-ray fixtures or
markers exist.

## 5. How to add a rung, or a measurement to one

1. The instrument writes a JSON report under `artifacts/` and is a script in the repo.
2. Add or edit an extractor in `tools/compare/ladder.py` that reads *only* that
   report. Every `fig(...)` names its reference and whether lower or higher is better;
   controls and oracles go in the second list.
3. Fill the registry row: MAMMA's stage, ours, the interface crossed, what MAMMA
   supplied in the rung, the blindness, and both substitution directions.
4. Run the ladder. Check the console for `NO CONTROL ARM`. Commit the report's
   generator, the page and the history line together.
5. Update the parity board card for that stage in the same pass and republish it to
   its existing URL (CLAUDE.md).

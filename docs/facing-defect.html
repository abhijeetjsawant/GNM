The Body Is Backwards

Every character this pipeline has ever delivered faces 180 degrees the wrong way. It survived because a wrong-but-self-consistent human still looks like a human — you only see it when you put the render beside the footage it came from, which nothing in the pipeline did until now.

What is actually wrong

The joints are driven correctly. It is the rig's left/right naming that is mirrored relative to the mesh it drives, and the retarget's frame alignment turns that mirror into a 180° yaw.

The blast radius is why this is not a one-line fix. DETAILED_HUMANOID is shared. The capture retarget, the generated speech and gesture lanes, the GLB exporter, the skin-binding matrices and the character-binding geometry all consume the same rig. If the generated lanes are mirrored too, they have been mirrored consistently and nobody noticed — and changing the convention moves all of them at once. Which end to fix — the rig naming or the retarget alignment — is a decision about which lane is authoritative, not a bug to patch quietly.
The instrument now exists. tools/swap-harness/camera_overlay.py renders the exported character from any rig camera's real extrinsics and intrinsics, so a render can always be held against the frame it came from. Every geometric error class — facing, scale, placement, limb assignment — is visible in that comparison and invisible without it. It should run on every capture.
